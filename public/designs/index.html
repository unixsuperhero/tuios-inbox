Behavior and integration boundary

These are UI designs, not a new TUIOS backend. Launch and completion are explicit simulations with sample data. Reloading a preview resets it. The production application and existing captures are unchanged.

A finished turn and a completed task are separate states. Opening a captured response marks it read; arrival never does. New responses leave the current answer, reading position and reply draft intact. The missing-response example shows a finished turn without claiming its output was captured.

For the real integration, a completion event should create a response record and notify the page. The UI should not subscribe to token output or infer completion from a quiet terminal. System notifications are not implemented in these designs; the persistent inbox count, page-title badge and in-page notification demonstrate the notification flow.
